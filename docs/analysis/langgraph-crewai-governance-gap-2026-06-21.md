## 1. 竞品概述

### 1.1 LangGraph（LangChain）

**定位：** 面向开发者的有状态Agent编排框架  
**核心能力：**
- 基于图结构的Agent工作流（节点=Agent/工具，边=流转逻辑）
- 支持循环、分支、条件路由等复杂编排模式
- StateGraph提供类型安全的状态管理
- 内置Checkpointing和Human-in-the-loop回调
- 支持Pregel算法并行执行

**目标用户：** Python/JS开发者，需要精细控制Agent执行流程的场景

**治理空白：**
- 没有内置审批流程（虽然有回调机制，但不是开箱即用的审批UI）
- 没有审计日志（Checkpointing是状态快照，不是操作审计）
- 没有执行成功率统计
- 没有human-in-the-loop的批量审批面板
- 没有重试/超时/错误处理的统一框架

### 1.2 CrewAI

**定位：** 多Agent协作框架  
**核心能力：**
- 角色定义（Role-Playing）：每个Agent有明确的角色、目标、 backstory
- 任务分配：Manager Agent协调多个Worker Agent
- 工具共享：多个Agent可以共享工具集
-  Sequential/Hierarchical两种协作模式

**目标用户：** 需要多Agent协作完成复杂任务的场景

**治理空白：**
- 完全没有审批机制
- 完全没有审计日志
- 完全没有human oversight
- Agent之间的协作是"黑盒"，无法追踪谁做了什么
- 没有错误恢复机制

## 3. 差异化策略

### 3.1 WFG的定位：不是编排工具，是治理中间件

**核心洞察：** LangGraph和CrewAI解决的是"Agent怎么协作"的问题，而WorkflowGuard解决的是"Agent协作后谁来负责"的问题。

**WFG的不可替代性：**
1. **审批流程** — 任何Agent的输出都需要人工确认才能执行
2. **全链路审计** — 谁在什么时候做了什么，不可篡改
3. **执行监控** — 成功率、耗时、错误率一目了然
4. **低代码** — 非技术人员也能管理和配置

### 3.2 合作而非竞争

**WFG可以与LangGraph/CrewAI集成：**
- 作为LangGraph的"治理层"插件
- 作为CrewAI的"审批中间件"
- 在Agent执行后、结果生效前，插入WFG的审批环节

**市场机会：** 随着Agent编排框架越来越强大，治理缺口也越来越大。WFG可以成为这些框架的"标准治理层"。

## 5. 结论

**WFG的差异化优势：**
1. 不做编排，做治理 — 与LangGraph/CrewAI互补而非竞争
2. 低代码+审批+审计 — 唯一面向非技术人员的Agent治理平台
3. 独立部署+数据主权 — 企业级安全要求
4. 模板化 — 开箱即用的客服/内容/数据审批流
