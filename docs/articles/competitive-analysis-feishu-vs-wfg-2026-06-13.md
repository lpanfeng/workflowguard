# 竞品分析：飞书审批流 vs WorkflowGuard — 差异化和市场切入

> 生成时间：2026-06-13 | 作者：攀峰 | WorkflowGuard 产品团队

---

## 一、竞品概述

### 飞书审批流
- **厂商**：字节跳动
- **定位**：企业协同办公套件中的审批模块
- **核心能力**：
  - 可视化审批模板编辑器（拖拽式）
  - 多级审批、会签、或签
  - 移动端（飞书App）原生体验
  - 与飞书消息、日历、文档深度集成
  - 开放API支持自定义审批流程
- **优势**：组织协同能力强、移动端体验优秀、用户基数大（字节生态）
- **劣势**：封闭生态、AI Agent 集成能力弱、无审计追踪、不可独立部署

### WorkflowGuard
- **定位**：人机协作工作流平台
- **核心能力**：
  - AI Agent 执行 → 人工审批 → 全链路审计
  - 三大模板：客服工单审批流、内容发布审批流、数据录入审批流
  - 独立部署、私有化部署支持
  - 审计日志完整留存
  - 多平台集成（飞书、Slack、邮件）
- **优势**：AI Agent 安全治理、独立部署、审计能力、产品专注度
- **劣势**：生态小、移动端体验待提升、飞书深度集成未完成

## 二、核心差异对比

| 维度 | 飞书审批流 | WorkflowGuard | WFG 胜出的关键 |
|------|-----------|---------------|--------------|
| **AI Agent 集成** | ❌ 不支持 | ✅ 核心能力 | 差异化最大点 |
| **审计追踪** | ❌ 仅有审批记录 | ✅ 全链路审计日志 | 合规刚需 |

| **组织协同** | ✅ 深度集成 | ⚠️ 基础 | 飞书胜 |
| **审批模板丰富度** | ✅ 丰富 | ⚠️ 3个模板 | 飞书胜 |
| **价格透明度** | ❌ 按企业套餐 | ✅ 按用量付费 | WFG胜 |
| **开发者友好度** | ⚠️ 飞书API | ✅ REST API + SDK | WFG胜 |

## 三、WFG 的差异化策略

### 3.1 主攻飞书覆盖不到的市场

1. **AI Agent 治理市场**（蓝海）
   - 飞书不做 Agent 安全
   - 随着 AI Agent 在企业中大规模部署，"谁审核 Agent 的执行结果" 成为刚需
   - WFG 是唯一专注此赛道的产品

2. **需要私有化部署的企业**
   - 金融、医疗、政府等行业有数据不出域的硬性要求
   - 飞书无法满足

3. **需要完整审计合规的企业**
   - SOC2、ISO27001 等合规要求全链路审计
   - 飞书的审批记录不够细粒度

### 3.2 与飞书共存而非竞争

**WFG 的定位不是替代飞书审批，而是增强飞书审批。**

- WFG 可以作为飞书审批的上游：Agent 执行 → WFG 审核 → 飞书归档
- WFG 通过飞书开放平台发送通知和接收回调
- 这种"飞书打底 + WFG 增强"的组合拳，比单独竞争更有说服力

### 3.3 目标客户画像

| 客户类型 | 痛点 | WFG 价值主张 |
|---------|------|------------|
| AI 创业公司 | Agent 执行结果无人审核 | 三段式治理框架 |
| 中大型企业 | 合规审计压力大 | 全链路审计日志 |
| 金融/医疗 | 数据不能出域 | 私有化部署 |
| 飞书重度用户 | 审批流程简单，无法满足复杂场景 | WFG 增强层 |

---

## 四、结论与建议

1. **短期**：聚焦 AI Agent 治理这一细分赛道，不做通用审批替代
2. **中期**：完善飞书集成，做"飞书 + WFG"组合方案
3. **长期**：建立 AI Agent 安全治理行业标准

> "不要和飞书比审批，要和飞书一起做生意。"
